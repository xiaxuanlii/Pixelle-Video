# 文档7：核心底层与工程实践源码阅读计划

在您掌握了《核心业务逻辑流转》（即三种生成模式和 Pipeline）的基础上，说明您已经构建起了项目的**宏观骨架**。为了更深入地理解项目的**微观实现**与**工程落地经验**，我们为您整理了这份进阶阅读路线图。

本指南聚焦于系统的**稳定性、扩展性、提示词工程以及长耗时任务处理**，这是区分“玩具脚本”与“商用级系统”的分水岭。

建议按照以下 4 个阶段，由浅入深地进行阅读。

---

## 阶段一：领域数据模型 (Domain Models) —— 万流归宗的数据结构

无论上层业务流怎么跳转，底层一定有一套标准的数据结构在承载信息。理解了数据结构，就能看懂所有模块之间的输入输出契约。

- **核心目标**：理解视频结构在内存中是如何定义的。
- **重点文件**：
  - `pixelle_video/models/storyboard.py`
  - `pixelle_video/models/media.py`

### 💡 核心看点：
1. **分镜设计 (`NarrationFrame` & `Storyboard`)**：
   观察它是如何把一段长文案拆解成帧的。注意它是如何将 `text`（旁白文本）、`duration`（语音时长）、`image_path`（生成的插图）、`video_path`（生成的视频）这些字段**绑定**在同一个对象上的。所有的 Pipeline 都是在给这几个字段填空。
2. **状态与上下文**：
   观察 Pydantic 库在数据校验和类型规范中发挥的作用。

---

## 阶段二：大模型交互与容错引擎 (LLM & Prompts) —— 提示词工程与防御性编程

AI 生成视频的质量上限，很大程度上取决于 LLM 输出脚本和提示词的质量。同时，LLM 的输出是不可控的，系统必须具备极强的容错性。

- **核心目标**：学习提示词框架设计，以及如何处理大模型输出的“脏数据”。
- **重点文件**：
  - `pixelle_video/prompts/` 目录（例如 `content_narration.py` 和 `video_generation.py`）
  - `pixelle_video/utils/content_generators.py`

### 💡 核心看点：
1. **提示词模版隔离 (`prompts/`)**：
   观察项目是如何将 Prompt 与代码逻辑分离的。看看它是如何约束大模型进行角色扮演、规定输出 JSON 格式、以及如何限制字数的。
2. **极限 JSON 容错 (`_parse_json` 方法)**：
   翻阅 `content_generators.py` 中的 `_parse_json` 函数。学习它是如何通过**多级降级策略**来修复大模型返回的数据的（1. 直接解析 -> 2. `json_repair` 库暴力修复 -> 3. 剥离 Markdown 标签 -> 4. 正则表达式强制提取内容）。这是非常宝贵的防御性编程实践。

---

## 阶段三：底层执行适配引擎 (Services) —— 屏蔽底层协议差异

业务层（Pipelines）只需要说“给我生成一段视频”，而 Services 层负责把这句人话翻译成阿里云、火山引擎、Kling 或本地 ComfyUI 能听懂的机器语言。

- **核心目标**：理解如何利用面向对象和抽象工厂模式来统一不同厂商的异构 API。
- **重点文件**：
  - `pixelle_video/services/api_services/` 目录（重点看 `llm_client.py`，`vlm_client.py` 以及各个 `*_dashscope.py` 等实现类）
  - `pixelle_video/services/comfy_base_service.py`

### 💡 核心看点：
1. **API 统一调用层 (`api_services/`)**：
   观察项目是如何抽象出 `ImageGenerator` / `VideoGenerator` 接口的。留意它是如何处理 API 的轮询等待、进度查询以及网络重试机制的。
2. **ComfyUI 适配器 (`comfy_base_service.py`)**：
   如果对工作流引擎感兴趣，看看这里是如何封装 `comfykit` 的。研究它是如何将简单的 Python 字典动态映射进庞大复杂的 ComfyUI JSON 节点图中，并如何监听 WebSocket 来获取生成进度的。

---

## 阶段四：异步任务调度系统 (API Backend) —— 现代 AI 后端基础设施

视频生成是典型的长耗时任务（几分钟到十几分钟）。如果让 HTTP 请求一直挂起等待（Sync），连接必定会超时中断。

- **核心目标**：掌握如何使用 Python 的 `asyncio` 构建基于内存的后台异步任务队列与状态轮询机制。
- **重点文件**：
  - `api/tasks/manager.py` 和 `api/tasks/models.py`
  - `api/routers/video.py`

### 💡 核心看点：
1. **基于内存的任务中心 (`manager.py`)**：
   观察 `TaskManager` 类。学习它是如何生成任务 UUID、如何使用 `asyncio.create_task` 将生成任务抛入后台、以及如何提供 `update_progress` 方法供底层服务汇报进度的。
2. **长短链接口模式对比 (`routers/video.py`)**：
   对比 `/generate/sync`（同步等待，适用于短任务）和 `/generate/async`（立刻返回 `task_id`，前端负责轮询 `/tasks/{task_id}` 获取进度）这两种路由设计的区别，这是构建高可用 AI 视频后端的标准范式。
