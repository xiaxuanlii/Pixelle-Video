# 开发协作与避坑指南

**目标读者**：贡献者、维护者。

## 代码规范与风格
- **静态检查**：项目全面拥抱了现代 Python 生态，使用 **Ruff** 进行代码 Lint（`select = ["E", "F", "I"]`），最大行宽限制为 100 行。
- **异步编程**：大规模使用了 `async/await`。所有 I/O 密集型操作（如网络请求 LLM、调用 ComfyUI 接口、异步执行 ffmpeg 进程）均实现了非阻塞协程。
- **类型提示**：依赖 `pydantic` 进行边界数据验证，代码内部有着极其规范的 Type Hints。

## 潜在风险与坑（Pitfalls）
1. **环境依赖深坑**：代码依赖了 `ffmpeg-python`。这只是一个 Wrapper！运行该程序的机器必须在系统级安装了真实的 `ffmpeg` 并配置在了环境变量中，否则视频合成环节必然报 `FileNotFoundError` 错误。
2. **并发控制陷阱**：在 `produce_assets` 阶段会使用 `Semaphore` 限制并发帧渲染量。修改此处需格外谨慎，如果并发数设得太高，不仅会触发 LLM 的 API Rate Limit，也会让本地 GPU 显存（运行 Comfy 节点时）瞬间 OOM (Out Of Memory)。
3. **跨模块作用域问题**：`api/app.py` 中有动态注入 `sys.path` 的 Hack 代码：`sys.path.insert(0, str(_project_root))`。这虽然解决了打包和本地运行找包的问题，但也意味着如果你使用相对引用的方式重构目录，可能会引发意料之外的 ModuleNotFound 错误。

## 测试建议
项目配置了 `pytest` 并启用了 `asyncio_mode = "auto"`。
- **单元测试**：针对 `models/` 中的数据验证逻辑，以及 `prompts/` 中的字符串拼装逻辑，应当编写无任何外部依赖的纯单元测试。
- **集成测试**：针对于 `pipelines`，建议编写 Mock 测试（使用 `unittest.mock.patch` 拦截 `httpx` 调用和 `ffmpeg` 调用），以防在 CI/CD 阶段产生高昂的 API 调用账单。
