# 文档 6：标准生成流程 (StandardPipeline) 源码阅读地图

本分文档旨在通过追踪一次完整的“从主题到视频”生成任务，帮助开发者快速定位和理解项目中的核心业务逻辑。

---

## 1. 业务流程概览 (Execution Lifecycle)

标准生成流程 (`StandardPipeline`) 的核心逻辑遵循 **“发散创意 -> 原子加工 -> 聚合输出”** 的模式。

### 核心阶段流转：
1.  **环境准备 (Setup)**:
    *   `pixelle_video/pipelines/standard.py` -> `setup_environment()`
    *   创建任务 ID (`task_id`) 和工作目录。
2.  **内容发散 (Content Generation)**:
    *   `pixelle_video/pipelines/standard.py` -> `generate_content()`
    *   调用 LLM 生成 5 段旁白 (`generate_narrations_from_topic`)。
3.  **视觉规划 (Visual Planning)**:
    *   `pixelle_video/pipelines/standard.py` -> `plan_visuals()`
    *   调用 LLM 生成每段旁白的绘图提示词 (`generate_image_prompts`)。
4.  **分镜原子加工 (Frame Production)**:
    *   `pixelle_video/pipelines/standard.py` -> `produce_assets()`
    *   循环调用 `FrameProcessor` 处理每一个分镜。
5.  **后期合成 (Post-Production)**:
    *   `pixelle_video/pipelines/standard.py` -> `post_production()`
    *   视频片段拼接 (`concat_videos`) 并混入 BGM (`add_bgm`)。
6.  **任务归档 (Finalize)**:
    *   保存元数据和分镜脚本 (`save_task_metadata`, `save_storyboard`)。

## 3. 关键技术路径深度解析

### 3.1 旁白驱动的音画对齐 (TTS-Driven Duration)
项目采用了“以音定画”的策略。
*   **逻辑位置**: `FrameProcessor._step_generate_audio`
*   **原理**: 首先生成 TTS 语音并获取其准确时长，然后将该时长传递给 `VideoService`。在渲染单图转视频时，强制指定视频时长等于音频时长，确保每一帧的画面与配音完美同步。

### 3.2 动态 HTML 模板渲染
区别于传统的图片叠加，本项目使用浏览器渲染引擎处理 UI 层。
*   **逻辑位置**: `FrameHTMLService.generate_frame`
*   **原理**: 加载 `templates/` 下的 HTML 模板，通过 JavaScript 将图片路径和旁白文本注入 DOM，最后截取浏览器快照。这种方式支持极其复杂的文字排版和样式效果。

### 3.3 云端 ComfyUI 工作流驱动
*   **逻辑位置**: `pixelle_video/services/media.py` -> `__call__`
*   **原理**: 客户端不直接生成图片，而是将 Prompt 填入 JSON 工作流模板，提交给 RunningHub 平台执行。这允许在低配机器上生成高质量的 SDXL/Flux 图像。

## 4. 调试与阅读建议

1.  **关注日志日志标记**:
    *   `[StandardPipeline]`：宏观流程日志。
    *   `[FrameProcessor]`：单个分镜的详细步骤。
    *   `[RunningHub/ComfyKit]`：云端生图的进度日志。
2.  **核心数据流**:
    *   所有的业务数据都承载在 `Storyboard` 模型类中 (`pixelle_video/models/storyboard.py`)。阅读代码时，重点观察 `StoryboardFrame` 对象的属性是如何被一步步填充的。
3.  **模板修改**:
    *   如果想改变视频风格，可以查看 `templates/1080x1920/` 下的 HTML 文件，配合 CSS 即可完成视觉改版。
